# 基于Web的《数据结构与算法》可视化演示系统

## 项目概述

本项目实现了一个基于 Web 前后端分离架构的算法可视化演示系统，核心功能为**堆的创建过程**可视化演示，并扩展支持**快速排序**算法。后端采用 Python (Flask + WebSocket)，前端采用原生 HTML5/CSS3/JavaScript + SVG，通过 WebSocket 实现实时双向通信，将算法分步执行过程以动画形式直观呈现。

## 系统架构

系统采用 **"前端交互层 → 后端服务层 → 算法执行层"** 三层前后端分离架构：

```
┌──────────────────────────────────────────────────────────┐
│                    前端交互层 (Browser)                    │
│  index.html  →  style.css  →  main.js                   │
│                         ↕                                │
│              socket.js (WebSocket)                       │
│         visualizer.js (SVG Canvas)                       │
├──────────────────────────────────────────────────────────┤
│              HTTP POST /api/submit                       │
│              WebSocket ws://host/ws                      │
├──────────────────────────────────────────────────────────┤
│                  后端服务层 (Flask)                       │
│  app.py  →  validator.py  →  algorithms/                 │
│                                                          │
│  HTTP API: 接收数据、触发算法生成步骤                       │
│  WebSocket: 实时推送步骤数据、接收前端控制指令               │
├──────────────────────────────────────────────────────────┤
│                  算法执行层 (Runner)                      │
│  heap.py     →  建堆步骤拆解                              │
│  quicksort.py → 快速排序步骤拆解                           │
└──────────────────────────────────────────────────────────┘
```

**核心交互流程：**
1. 前端接收用户输入 → HTTP POST 提交至后端
2. 后端校验数据 → 调用算法执行器 → 生成标准化步骤数据列表
3. 后端通过 WebSocket 逐步骤推送至前端
4. 前端接收步骤数据 → SVG 实时渲染可视化动画 + 同步更新步骤文字说明
5. 用户可随时发送暂停/继续/重置指令控制演示节奏

## 各模块作用详述

### 一、后端模块

#### 1. `backend/app.py` — 后端主服务

- **角色**：后端核心入口，整合所有后端模块
- **职责**：
  - 启动 Flask Web 服务器（端口 5000）
  - 集成 `flask-sock` WebSocket 扩展和 `flask-cors` 跨域支持
  - 定义 `POST /api/submit` 接口：接收前端提交的输入数据与算法类型
  - 定义 `WebSocket /ws` 路由：管理 WebSocket 连接的生命周期
  - **多用户会话管理**：通过 `session_id`（UUID）区分不同用户的步骤数据，存储在全局字典 `sessions` 中，避免多用户数据错乱
  - **步骤推送线程**：收到前端 `start` 指令后，启动独立线程逐步骤推送算法数据，支持通过 `threading.Event` 控制暂停/继续
  - **连接生命周期管理**：处理 WebSocket 连接建立、消息接收、断开清理

#### 2. `backend/validator.py` — 数据校验模块

- **角色**：输入数据合法性校验
- **职责**：
  - 校验输入是否为数组格式
  - 校验数组中每个元素是否为整数类型
  - 根据算法类型进行特定校验（如堆创建要求2~31个整数，快速排序要求2~20个整数）
  - 校验失败时返回明确的错误提示信息，校验通过返回解析后的数组
  - 双重保障：前端预校验（提升体验）+ 后端校验（确保安全性）

#### 3. `backend/algorithms/heap.py` — 堆创建步骤拆解

- **角色**：将"建堆"算法执行过程拆解为标准化步骤数据
- **核心逻辑**：
  - 从最后一个非叶子节点（索引 `n//2-1`）开始，逐一向根节点执行**下沉（sift-down）**操作
  - 每一步记录：当前操作节点索引、比较节点索引、数组当前状态、是否发生交换
  - 记录的步骤类型包括：开始调整节点、与左子节点比较、与右子节点比较、交换操作、调整完成
  - 初始状态和最终完成状态各生成一条步骤
- **输出格式**：统一的 JSON 步骤数据列表，每个步骤包含 `step_id`、`algorithm`、`description`、`array`、`highlight`、`compare`、`swap`、`status` 等字段

#### 4. `backend/algorithms/quicksort.py` — 快速排序步骤拆解

- **角色**：将快速排序的执行过程拆解为标准化步骤数据
- **核心逻辑**：
  - 使用 **Lomuto 分区方案**，以最右侧元素为 pivot
  - 递归处理每个子数组，记录每次比较（`arr[j]` vs pivot）和每次交换操作
  - 记录分区开始、pivot 选择、元素比较、元素交换、pivot 归位、递归处理等完整流程
  - 基准情况（单元素区间）也生成步骤说明
- **输出格式**：统一的 JSON 步骤数据，额外包含 `pivot_idx`、`left_ptr`、`right_ptr` 等快速排序特有字段

#### 5. `backend/requirements.txt` — 依赖清单

- 列出后端所需的 Python 第三方包：`flask`（Web 框架）、`flask-sock`（WebSocket 扩展）、`simple-websocket`（WebSocket 后端实现）、`flask-cors`（跨域支持）

### 二、前端模块

#### 6. `frontend/index.html` — 页面布局

- **角色**：前端页面的骨架，定义四大核心区域
- **包含区域**：
  - **顶部标题栏**：系统名称 + 实时状态徽章（就绪/演示中/已完成/错误）
  - **输入控制区域**：数据输入框 + 算法选择下拉框（堆创建/快速排序）+ 速度选择（快/正常/慢）+ 提交/暂停/继续/重置按钮
  - **步骤说明区域**：实时展示当前算法步骤的文字描述，配有当前步骤编号
  - **可视化渲染区域**：SVG 画布（800×450 viewBox），用于绘制算法可视化动画
  - **页脚提示区域**：操作提示与错误信息展示
- JavaScript 脚本按依赖顺序加载（`socket.js` → `visualizer.js` → `main.js`）

#### 7. `frontend/style.css` — 样式设计

- **角色**：定义页面视觉样式，确保布局合理、交互反馈明显
- **设计要点**：
  - 全局居中布局，最大宽度 900px，各区域间距 16px
  - 按钮按功能区分颜色：提交（蓝色）、暂停（橙色）、继续（绿色）、重置（红色），含 hover 和 disabled 状态
  - 状态徽章根据状态变色（绿色就绪、橙色演示中、红色错误）
  - 步骤说明区域左侧带蓝色边条，增强可读性
  - SVG 容器使用 16:9 宽高比，带圆角边框
  - 定义 `@keyframes nodePulse`（节点脉冲动画）和 `@keyframes fadeIn`（淡入动画）供可视化模块使用

#### 8. `frontend/socket.js` — WebSocket 通信模块

- **角色**：管理前后端 WebSocket 长连接，封装数据收发逻辑
- **核心功能**：
  - **连接建立**：页面加载后自动连接后端 WebSocket（`ws://host/ws`），成功后接收后端确认信息
  - **数据接收**：监听 `onmessage` 事件，将后端推送的 JSON 步骤数据解析后转发给注册的消息处理器（`visualizer.js`）
  - **指令发送**：暴露 `send()` 方法供 `main.js` 调用，向前端暴露统一的通信接口
  - **状态监听**：提供 `onStatusChange()` 注册机制，供主逻辑监听连接状态变化
  - **断线重连**：连接异常断开时自动尝试重连（最多 5 次，递增间隔），避免演示中断

#### 9. `frontend/visualizer.js` — SVG 可视化渲染模块

- **角色**：将后端推送的标准化步骤数据转化为 SVG 动画，实现算法过程的可视化
- **渲染模式**：
  - **堆创建**：以树形结构绘制（圆形节点 + 数值文字 + 父子连接线），节点位置预定义为 800×450 画布上的坐标，最多支持 4 层共 15 个节点
  - **快速排序**：以数组条形图绘制（矩形柱 + 数值标签 + 索引标签），高度与数值成正比
- **分步渲染逻辑**：
  - 解析步骤数据中的 `highlight`（高亮节点，红色）、`compare`（比较节点，黄色）、`pivot_idx`（pivot，紫色）等字段，为对应元素设置不同颜色
  - 交换操作时绘制虚线箭头指示器，0.8 秒后自动消失
  - 使用 CSS 过渡（`transition`）实现颜色渐变和位置平滑变化
  - 演示完成时所有节点变为绿色，表示最终状态

#### 10. `frontend/main.js` — 前端主逻辑控制器

- **角色**：整合前端所有模块，协调用户交互与完整演示流程
- **核心流程**：
  - **页面初始化**：建立 WebSocket 连接，注册消息处理器与状态监听器，绑定按钮事件
  - **输入解析与预校验**：将逗号分隔的字符串解析为整数数组，检查格式与长度
  - **HTTP 请求提交**：通过 `fetch` 将数据 POST 到后端 `/api/submit`，接收 `session_id`
  - **演示启停控制**：
    - 提交成功 → 调用 `Visualizer.init*()` 初始化画布 → 发送 WebSocket `start` 指令
    - 暂停/继续 → 发送 `pause`/`resume` 指令，更新按钮状态
    - 重置 → 发送 `reset` 指令，清空所有状态、输入框、画布
  - **演示完成处理**：接收到 `completed` 消息后禁用操作按钮，显示完成状态
  - **错误处理**：网络请求失败、WebSocket 断开、后端返回错误时，在页脚显示明确提示

## 关键技术点

| 技术点 | 实现方式 |
|--------|---------|
| 前后端解耦 | HTTP REST API + WebSocket，数据格式约定为统一 JSON |
| 实时双向通信 | WebSocket 全双工协议（`flask-sock` 后端 + 原生 WebSocket API 前端） |
| 算法步骤拆解 | 每种算法独立模块，将"只输出结果"改为"记录每一步操作" |
| 可视化渲染 | SVG 树形节点图（堆）+ SVG 条形图（快速排序），CSS 过渡动画 |
| 会话隔离 | 后端以 UUID 区分用户，每个 WebSocket 连接独立推送线程 |
| 交互控制 | `threading.Event` 实现暂停/继续，独立线程推送 |
| 跨域支持 | `flask-cors` 处理后端跨域 |

## 运行方式

### 1. 安装后端依赖

```bash
cd backend
pip install -r requirements.txt
```

### 2. 启动后端服务

```bash
cd backend
python app.py
```

后端将在 `http://localhost:5000` 启动，WebSocket 地址为 `ws://localhost:5000/ws`。

### 3. 打开前端页面

直接用浏览器打开 `frontend/index.html`，或用 VS Code Live Server 等方式。

### 4. 使用流程

1. 在输入框中输入整数（逗号分隔），选择算法类型和演示速度
2. 点击**提交**，后端校验数据并生成步骤
3. 可视化区域自动开始动画演示，步骤说明区域同步展示文字描述
4. 可随时点击**暂停/继续**控制演示节奏，点击**重置**恢复到初始状态
